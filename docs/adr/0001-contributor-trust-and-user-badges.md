# KidsWiki 권한·승격·강등·뱃지 시스템

## 목적

KidsWiki의 사용자 상태는 역할, 기여 신뢰, 사용자 뱃지라는 세 축으로 나뉜다. 이 문서는 각 축이 무엇을 결정하는지, 신뢰 기여자가 어떻게 승격·강등되는지, 운영자가 어떤 기준으로 상태와 뱃지를 관리하는지 설명한다.

기존의 가입 15일 또는 과거 편집 여부를 이용한 전역 신뢰 판정은 사용하지 않는다. 가입 기간은 실제 기여 품질을 보여주지 못하고, 운영 권한·직접 게시 권한·전문 자격을 하나의 등급으로 묶으면 의미가 흐려지기 때문이다.

## 한눈에 보기

| 축 | 답하는 질문 | 가능한 상태·예시 |
| --- | --- | --- |
| 역할 | 사이트 운영 기능을 사용할 수 있는가? | 일반 사용자, 토론 관리자, 관리자, 최고 관리자 |
| 기여 신뢰 | 자신의 위키 편집을 바로 게시할 수 있는가? | 일반 기여자, 신뢰 기여자 |
| 사용자 뱃지 | 운영진이 확인한 자격이나 특성이 있는가? | 자격 확인 전문가 |

세 축은 서로 독립적이다. 예를 들어 자격 확인 전문가 뱃지를 단 일반 기여자는 편집 등록 요청이 필요하고, 전문 자격 뱃지가 없는 신뢰 기여자는 자신의 편집을 바로 게시할 수 있다.

## 1. 역할과 운영 권한

역할은 사이트 운영 권한을 결정한다. 상위 역할은 하위 역할의 권한을 물려받는다.

| 역할 | 주요 권한 |
| --- | --- |
| 비회원 | 공개 위키 읽기 |
| 일반 사용자 | 위키 편집 기능 이용, 댓글 작성, 티켓 생성, 미디어 업로드 |
| 토론 관리자 | 일반 사용자 권한 + 토론 상태 관리, 토론·댓글 소프트 삭제, 토론형 티켓 관리 |
| 관리자 | 토론 관리자 권한 + 편집 요청 검토, 관리자 화면, 문서·사용자·티켓 관리 |
| 최고 관리자 | 모든 권한과 전역 설정·역할 관리 |
| 차단·탈퇴 사용자 | 권한 없음 |

`wiki:edit` 권한은 편집 기능을 사용할 수 있다는 뜻이지, 항상 즉시 게시할 수 있다는 뜻은 아니다. 즉시 게시 여부는 기여 신뢰와 편집 요청 설정이 별도로 결정한다.

토론 관리자는 토론을 관리하는 역할이다. 다른 사용자의 위키 편집 요청을 승인·반려하거나 사용자·문서를 전반적으로 관리하는 역할은 아니다.

## 2. 위키 편집의 게시 결정

`EDIT_REQUEST_ENABLED=true`일 때 게시 흐름은 다음과 같다.

1. 역할에 `wiki:edit` 권한이 있어야 편집할 수 있다.
2. 문서별 편집 ACL을 확인한다.
3. 관리자 또는 신뢰 기여자의 편집은 바로 반영한다.
4. 일반 기여자의 편집은 등록 요청으로 보관하고 관리자가 승인·반려한다.

| 사용자 상태 | 자신의 편집 | 타인의 편집 요청 검토 |
| --- | --- | --- |
| 일반 기여자 | 등록 요청 | 불가 |
| 신뢰 기여자 | 바로 게시 | 불가 |
| 관리자·최고 관리자 | 바로 게시 | 가능 |

관리자도 자신이 작성한 등록 요청을 직접 승인·반려할 수 없다. 승인과 반려 결과는 요청 작성자의 신뢰 평가 기록에 반영된다.

되돌리기, 이미지 문서 직접 수정, MCP 편집 직접 반영처럼 등록 요청으로 보류할 수 없는 작업은 신뢰 기여자 또는 관리자만 사용할 수 있다. 신뢰 기여자는 자신의 편집을 바로 게시할 수 있을 뿐, 검토자 권한을 얻지는 않는다.

### 문서별 편집 ACL과의 관계

문서별 ACL은 역할·신뢰와 별도로 적용한다.

- `admin_only` 문서는 관리자만 편집할 수 있다. 신뢰 기여자도 예외가 아니다.
- `aged`, `page_editor`, `any_editor` 같은 조건을 일반 사용자가 충족하지 못하더라도 편집 요청 기능이 켜져 있으면 등록 요청을 제출할 수 있다.
- `edit_acl_min_age_days`는 `aged` ACL이 붙은 문서에만 쓰는 기준이다. 전역 신뢰나 신뢰 기여자 승격 기준이 아니다.

`EDIT_REQUEST_ENABLED=false`는 편집 요청 제도 전체를 끄는 운영용 차단 스위치다. 이때는 기존 역할과 문서 ACL이 허용하는 편집이 바로 반영되며, 신뢰 기여자 전용 직접 게시 제한도 적용하지 않는다.

## 3. 신뢰 기여자 자동 승격

신뢰 상태는 다음 두 가지다.

- 일반 기여자(`standard`): 자신의 편집을 등록 요청으로 제출한다.
- 신뢰 기여자(`trusted`): 자신의 편집을 등록 요청 없이 게시한다.

자동 평가는 편집 요청의 승인·반려 결과를 신뢰 이벤트 원장에 기록하고, 그 기록으로 계산한다. 분야별 기여 현황이나 단순 편집 횟수는 참고 정보이며 자동 승격 점수로 사용하지 않는다. 신뢰 기여자가 된 뒤 바로 게시한 편집도 승인 건수에 추가되지 않는다.

승인 기여일은 관리자가 승인한 날짜가 아니라 사용자가 해당 요청을 마지막으로 제출한 날짜를 기준으로 센다. 관리자가 여러 요청을 한꺼번에 검토해도 사용자의 실제 기여 시점이 바뀌지 않게 하기 위해서다. 날짜 경계는 KidsWiki 운영 시간대인 한국 표준시를 사용한다.

### 승격 조건

자동 모드에서는 다음 조건을 모두 충족해야 한다.

| 기준 | 조건 |
| --- | --- |
| 승인 건수 | 3건 이상 |
| 기여 문서 수 | 서로 다른 문서 2개 이상 |
| 승인 기여일 | 서로 다른 제출일 3일 이상 |
| 승인률 | 80% 이상 |

승인률은 `승인 건수 / (승인 건수 + 반려 건수)`로 계산한다. 같은 날 여러 요청이 승인되어도 승인 기여일은 하루로 센다. 네 조건 중 하나라도 부족하면 일반 기여자로 남는다.

조건을 충족한 편집 요청이 처리되면 즉시 신뢰 기여자로 승격하고 사용자에게 알린다. 단순 비활동은 승격을 취소하거나 신뢰를 낮추는 사유가 아니다.

## 4. 신뢰 기여자 강등

승인·반려와 별도로, 관리자는 사유를 적어 문제 기여를 기록할 수 있다.

| 문제 기록 | 자동 강등 기준 |
| --- | --- |
| 문제 기여(`problematic`) | 최근 90일 안에 2건 |
| 심각한 문제 기여(`severe`) | 최근 90일 안에 1건 |

기준에 도달하면 자동 모드의 신뢰 기여자를 즉시 일반 기여자로 강등하고 사용자에게 사유를 알린다. 반려 기록만으로 이미 신뢰 기여자인 사용자를 자동 강등하지는 않는다. 강등은 관리자가 별도로 남긴 문제 기여 기록을 기준으로 한다.

운영상 단순 오탈자나 취향 차이는 문제 기여로 기록하지 않는 편이 좋다. 사실관계·출처·정책상 의미 있는 문제가 반복되면 `problematic`, 고의적 훼손이나 위해 가능성이 큰 허위 정보처럼 즉시 신뢰를 거둬야 하면 `severe`를 사용한다. 이는 운영 판단을 돕는 권고이며, 시스템은 필수 사유와 문제 수준만 검증한다.

### 재승격

강등 시 새 평가 주기를 시작하고 이전 주기의 승인·반려 실적을 다시 사용하지 않는다. 재승격하려면 다음 조건을 모두 충족해야 한다.

1. 강등 뒤 최소 30일의 재승격 대기 기간이 끝나야 한다.
2. 새 평가 주기에서 승인 3건, 문서 2개, 서로 다른 제출일 3일, 승인률 80%를 다시 충족해야 한다.
3. 최근 90일 문제 기록이 자동 강등 기준보다 낮아야 한다.

따라서 30일은 최소 대기 기간이지 재승격을 보장하는 기간이 아니다. 심각한 문제 1건처럼 90일 기준이 계속 충족되면, 대기 기간과 새 기여 기준을 채워도 해당 기록이 90일 범위에서 벗어나기 전까지 자동 재승격되지 않는다.

## 5. 자동 평가와 관리자 고정

관리자는 사용자별로 신뢰 모드를 선택할 수 있다.

| 모드 | 동작 |
| --- | --- |
| 자동 평가(`auto`) | 승인·반려·문제 기록과 정책 기준으로 승격·강등한다. 기본값이다. |
| 신뢰 기여자 고정(`trusted`) | 자동 평가 결과와 관계없이 신뢰 기여자로 유지한다. |
| 일반 기여자 고정(`standard`) | 자동 승격 조건을 충족해도 일반 기여자로 유지한다. |

고정 모드에서도 승인·반려·문제 이벤트는 원장에 남는다. 다시 자동 평가로 전환하면 현재 원장, 평가 주기, 대기 기간을 기준으로 즉시 재계산한다. 관리자가 상태를 바꾸거나 문제 기여를 기록하면 관리자 로그와 사용자 알림을 남긴다.

## 6. 사용자 뱃지

사용자 뱃지는 운영진이 확인한 자격이나 특성을 공개 프로필에 표시한다. 뱃지는 역할이나 신뢰 상태를 바꾸지 않으며, 편집·검토·관리 권한을 부여하지 않는다.

현재 등록된 뱃지는 다음과 같다.

| 뱃지 | 의미 | 부여 방식 |
| --- | --- | --- |
| 자격 확인 전문가(`verified_expert`) | 운영진이 외부 전문 자격을 확인한 사용자 | 관리자가 확인 뒤 부여·회수 |

일반 사용자, 신뢰 기여자, 토론 관리자, 관리자 모두 확인된 자격이 있으면 같은 뱃지를 달 수 있다. 한 사용자에게 여러 뱃지를 동시에 부여할 수 있고, 부여·회수 시 관리자 로그와 사용자 알림을 남긴다.

뱃지 종류와 표시 정보는 공통 카탈로그에서 관리한다. 새 뱃지는 카탈로그에 정의하면 관리자 화면과 공개 프로필이 같은 정보를 사용한다. 다만 실명 인증처럼 별도 검증이 필요한 뱃지는 검증 절차, 증빙 보관 범위, 만료·회수 기준을 먼저 정한 뒤 추가한다.

## 7. 조합 사례

| 사용자 | 역할 | 신뢰 | 뱃지 | 실제 동작 |
| --- | --- | --- | --- | --- |
| 자격이 확인된 신규 기여자 | 일반 사용자 | 일반 | 자격 확인 전문가 | 편집은 등록 요청, 프로필에는 전문 자격 표시 |
| 기여 품질이 쌓인 사용자 | 일반 사용자 | 신뢰 | 없음 | 자신의 편집은 바로 게시, 타인 요청 검토는 불가 |
| 토론 운영 담당자 | 토론 관리자 | 일반 | 없음 | 토론은 관리하지만 자신의 위키 편집은 등록 요청 |
| 전문 자격이 있는 관리자 | 관리자 | 신뢰 여부와 무관 | 자격 확인 전문가 | 관리자 권한으로 직접 게시·검토, 프로필에는 전문 자격 표시 |

## 8. 기록과 계정 병합

승인, 반려, 문제 기여, 심각한 문제 기여는 중복되지 않는 이벤트 원장으로 보관한다. 현재 신뢰 상태와 모드, 평가 주기, 재승격 대기 시각은 사용자별 신뢰 상태에 보관한다. 뱃지는 사용자와 뱃지 키의 조합으로 따로 보관한다.

계정을 병합하면 신뢰 이벤트와 뱃지를 대표 계정으로 합치고 대표 계정의 신뢰 상태를 다시 계산한다. 공개 프로필에는 신뢰 기여자 여부와 사용자 뱃지만 표시하며, 내부 운영 역할은 기존 공개 정책대로 숨긴다.

## 결정 결과

- 역할은 운영 권한만 나타낸다.
- 신뢰 상태는 자신의 편집을 바로 게시할 수 있는지만 나타낸다.
- 뱃지는 확인된 사용자 특성만 나타낸다.
- 타인의 편집을 검토하는 권한과 전문 자격은 어떤 경우에도 자동으로 따라오지 않는다.

정책 상수의 기준 구현은 `src/utils/contributorTrust.ts`, 역할 권한은 `src/utils/role.ts`, 뱃지 카탈로그는 `src/utils/userBadges.ts`에 있다. 용어 정의는 `CONTEXT.md`를 따른다.
